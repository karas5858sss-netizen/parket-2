# ПАР·КЕТ — расписание для двоих

Telegram Mini App: расписание двух человек из разных вузов, ДЗ, отметки, свои пары, календарь, поиск,
итоги, вечернее напоминание от бота и журнал «что изменилось в расписании». Хостинг: Vercel (бесплатный план),
база: Upstash Redis, сервер расписания вуза читается через свой прокси.

## Карта файлов

| Файл | За что отвечает |
|---|---|
| `index.html` | Оболочка: подключает стили и скрипты, показывает сообщение, если какой-то файл не загрузился |
| `css/app.css` | Все стили, цвета берутся из переменных темы (светлая, тёмная, как в Telegram) |
| `js/core.js` | Telegram, localStorage, тема, даты, константы: палитра (16 цветов), сетка пар `SLOTS`, версия сборки `BUILD` |
| `js/state.js` | Состояние приложения, загрузка расписания и журнала, ДЗ/отметки/свои пары, очередь несохранённого |
| `js/domain.js` | Логика без HTML: ключи предметов, свои пары в карточки, журнал изменений, номера пар, общие окна |
| `js/cards.js` | HTML-кусочки: карточка пары, блок «что изменилось», карточка партнёра, общие окна |
| `js/views.js` | Экраны: Сегодня, Неделя, Месяц, Предметы, Поиск, Итоги |
| `js/sheets.js` | Нижние листы и формы: ДЗ, настройки, своя пара, «отменить», подтверждение |
| `js/app.js` | `render()`, обработка нажатий, таймеры, запуск |
| `api/schedule.js` | Прокси расписания вуза (ID групп в `PROFILES`, менять раз в год) |
| `api/state.js` | Общее хранилище: ДЗ, отметки, цвета, свои пары, настройки; проверка подписи Telegram |
| `api/notify.js` | Вечернее напоминание (Vercel Cron) и «прислать пример сейчас» |
| `api/changes.js` | Журнал изменений расписания |
| `lib/shared.js` | Общее для сервера: проверка подписи, Redis, белый список, адрес приложения |
| `lib/digest.js`, `lib/changes.js`, `lib/detect.js`, `lib/slots.js` | Текст напоминания, сравнение версий расписания, запись изменений, сетка пар |
| `vercel.json` | Cron: `0 17 * * *` по UTC, то есть около 20:00 по Москве |
| `tests/` | Тесты (клиент и сервер), см. ниже |

**Порядок скриптов в `index.html` важен:** core → state → domain → cards → views → sheets → app.
Файл может использовать только то, что объявлено в файлах выше него (или вызывать функции ниже уже во время работы).
Файлы делятся одной областью видимости: имя функции или константы не должно повторяться в двух файлах.

## Как править, чтобы ничего не ломать

1. Найди файл по таблице выше и правь **только его**. Новую функцию клади в файл по смыслу.
2. **Заливай все изменённые файлы одним коммитом.** Если залить `index.html` без нового `js`-файла (или наоборот),
   приложение покажет сообщение «не найдены файлы: …».
3. После заливки открой на GitHub коммит: **зелёная галочка** значит тесты прошли, **красный крестик** значит что-то сломалось,
   открой «Details» и посмотри, какая проверка красная. Не оставляй красное надолго.
4. Меняй `BUILD` в `js/core.js` при каждой выкладке. Версия видна внизу «Настроек» и помогает понять, что телефон получил свежие файлы.
5. Две вещи хранятся в двух местах и меняются вместе: сетка пар (`SLOTS` в `js/core.js` и `lib/slots.js`)
   и подписи «Кирилл/Маша» (`LABEL` в `js/core.js`, `NAMES` в `lib/digest.js`).
6. Новую функцию не называй как встроенное имя браузера (`name`, `top`, `open`, `status`…): тест `client-global-names` это проверяет.

## Тесты

```
cd tests
npm install
npm test
```
Клиент проверяется в эмулированном браузере (jsdom) с подменой Telegram и сервера, сервер с имитацией Redis, Telegram и расписания вуза.
На GitHub тесты запускаются сами при каждой заливке (`.github/workflows/tests.yml`).
Чего тесты **не** умеют: они не видят реальный Telegram, реальный сервер вуза и внешний вид на телефоне. Это надо проверять глазами.

## Переменные окружения (Vercel → Settings → Environment Variables)

| Имя | Зачем |
|---|---|
| `BOT_TOKEN` | Токен бота из @BotFather. Секрет: только сюда, никому не присылать |
| `ME_TG_ID`, `HER_TG_ID` | Telegram ID Кирилла и Маши (белый список доступа) |
| `CRON_SECRET` | Любая длинная случайная строка, Vercel Cron передаёт её при запуске напоминания |
| `APP_URL` | `https://parket-2.vercel.app`. Основной адрес приложения; рекомендуется задать явно |
| Upstash Redis | Подключается через Vercel → Storage, переменные появляются сами |

После добавления или изменения переменной нужен Redeploy.

## Если что-то пошло не так

**Напоминание в 20:00 не пришло.** На бесплатном плане Vercel запускает cron в любой момент внутри часа (20:00–20:59 по Москве).
1. Есть ли `CRON_SECRET` в Production (Settings → Environment Variables)? Без него cron получает отказ (ответ 503), хотя «Прислать пример сейчас» работает. Эта кнопка в «Настройках» сама предупредит, если переменной нет.
2. Settings → Cron Jobs: есть ли `/api/notify`? Кнопка **Run** запускает его сразу.
3. Project → Logs, фильтр по `/api/notify`: строка `notify {...}` показывает, что произошло с каждым из двоих
   (`sent`, `skipped: disabled` это выключено в «Настройках», `schedule_unavailable`, ошибка Telegram).
4. Маша должна была открыть чат с ботом и нажать Start. Без этого бот не может ей писать.
5. Проверка без ожидания: «Настройки» → «Прислать пример сейчас».

**Расписание не грузится.** Открой `/api/schedule?profile=me` и `?profile=her` в браузере. Если пусто, проверь `PROFILES` в `api/schedule.js`:
ID групп меняются каждый учебный год.

**ДЗ «недоступно».** `/api/state` вернул 503: не настроена база Upstash или `BOT_TOKEN`; 403: чей-то ID не в `ME_TG_ID`/`HER_TG_ID`
(приложение само покажет ID).

**Изменилось расписание звонков.** Правь `SLOTS` в `js/core.js` и `lib/slots.js`.
